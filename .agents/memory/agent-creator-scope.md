description: User-requested replacement for the Short Sprints subscriber feature.

Replace the subscriber-facing SHORT SPRINTS feature with AGENT CREATOR as a
Category A path. At the appropriate F stage, MA creation should offer an
immediately usable MA agent with its Micro PDD, and SPC creation should offer
an SPC agent with its Cheat Sheet. Bring MATHMON, JCSE, ethical/governance
engines and applicable integrations into that guided creation flow. Fast-track
the resulting work toward F10, F11 and F12, and route every artifact download
through IMPRIMA PORTAL.

**Why:** The user wants the production floor to create useful governed agents
without making subscribers repeat scattered steps and gates. Historical sprint
records remain meaningful even as the subscriber-facing feature is replaced.

**How to apply:** Keep pre-existing sprint records/history intact. A guided
fast-track is orchestration of real checks, not a bypass: inherited scores,
governance content, connector receipt, provider execution and independently
verified release are separate facts. Do not claim F12 operation or a published
download until its actual infrastructure and IMPRIMA controls work.

The user selected **both where eligible** for initial agent operation: an
ARK-run agent and a connected third-party target when each actually qualifies.
Do not silently prefer one destination or label a delivery receipt as a running
agent.

Stage controls are active only at F3/F4 when the exact MA + saved Micro PDD pair
exists, or at F5 after an SPC is saved. They stay inactive at all other stages.
For an SPC, create and save its Cheat Sheet before drafting, evaluation and activation.

**Why:** The user confirmed F3/F4/F5 after the existing stage numbering was explained,
and requested an artifact-triggered glow/vibration cue rather than always-active controls.

**How to apply:** Check exact lineage and same-session pairing on the server as well as
the UI. Respect reduced-motion settings. A first-step Cheat Sheet does not authorize
execution, certification or external release.

SPC Cheat Sheets must include nine fields: SPC name, project file name, synthesized
SPC lineage, date/time, Junglenomics skill sets, target-specific SAVANT colonization
guidance, stated constraints/ethical integrations, author and owner.

**Why:** The user explicitly requires author and owner to be separate because an
Enterprise subscriber's owner may differ from its author.

**How to apply:** Preserve source declarations as declarations; distinguish workspace
custody from legal IP ownership. Mark absent metadata as unrecorded, never invent
lineage, identity, skills or a completed SAVANT/ethical verification.
