---
name: SPC Player REVERB and open delivery contract
description: Durable runtime, access, delivery, and lease boundaries for SPC Player
---

SPC Player uses the user-authorized REVERB v3 replacement as a conservative,
generic adaptation. Execution is sequential and owned by the requesting user;
retain each actual verdict and evidence item, and do not infer source-specific
editorial behavior or expand the supported card contract.

The default remains PRE_BUILD with plan-only distribution. The explicitly
authorized project-owned replacement is nevertheless open access: provide
deterministic JSON packaging and built-in download, and allow public-HTTPS
webhook delivery only after explicit per-run consent. Open access introduces no
entitlement, tier, credit, billing, pricing, or LLM gate. Keep access status
separate from certification maturity.

Provider calls use the existing cost-budget and run-recording path. Persist
independent clarity, truthfulness, and detectability axes; never invent a
composite score. Preserve DRAFT/RUNNING/COMPLETED/FAILED transitions and
provider failures. Environment entries marked as sketches remain documentation,
not verified integrations.

Concurrent execution claims require a unique per-attempt token and a
conservative expiring lease longer than one provider call. Every progress,
failure, evaluation, and completion write must fence on the token and running
status. A stale worker must never overwrite a newer attempt; an expired
running attempt may be recovered with an explicit recovery transition.

**Why:** REVERB authorizes a narrow generic runtime, while task 181 explicitly
authorizes open access and connector delivery. Keeping execution plan-only by
default, requiring consent for outward delivery, and separating access from
certification prevents unsupported product semantics without revoking the
authorized delivery path.

**How to apply:** Keep download available after execution and require
ownership for every run action. Persist webhook consent per run. For every
server-side connector, reject private-network destinations and pin a validated
public destination for the request so DNS changes cannot redirect delivery to
private systems. Preserve authorization across reloads and keep access open
while certification remains PRE_BUILD.
