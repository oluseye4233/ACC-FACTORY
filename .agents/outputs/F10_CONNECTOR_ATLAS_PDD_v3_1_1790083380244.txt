1.1 Atomic Solution Summary
F10 CONNECTOR takes an artifact that has passed F0 through F9.5
and connects it to an implementation platform through an automated

colonization process governed by the SAVANT Protocol. It senses the
target, obtains a verdict from the SAVANT engine, names every gap,
translates the artifact into the target's native form, stages it, verifies it,
certifies it, promotes it, and registers the outcome.
It automates the steps around SAVANT. It never replaces SAVANT, and
it holds no verdict of its own.
The floor has exactly one operator: SAVANT ENVOY ULTRA SI. It runs
the nine phases, invokes the external gates, and produces either a
staged, verified, certified and registered colonization, or a cited refusal.
It owns no gate it runs and can override no verdict it receives.

1.8 What This Document Does Not Claim
F10 is PRE-BUILD. No connector, conductor, or adapter exists.
Nothing has touched any real platform.
No SAVANT engine is wired. F10 can be built and will refuse at C1
until one is. See §1.9.
The colonized-deployment certificate class does not exist. UCG-
COL has no threshold, so promotion is unreachable until one is set
(OI-10).
The operator is specified and unbuilt. SAVANT ENVOY is PRE-
BUILD, self-scored at JCSE 41/50 (Tier 0, below the 45 floor), and
has never run. No live connector has been assessed (OI-09,
narrowed).
Curated prompt wording is synthesized, not retrieved. The facts a
prompt relies on (what the target's chat assistant is documented to
accept) must be sensed or supplied with provenance. The phrasing
of the prompt itself is composed for the run and is [SYNTH] , not
[ARK] , even when every fact behind it is sourced. Whether that line
is drawn correctly is unadjudicated (OI-40).
No scanner is wired for chat-transcript intake (OI-38), and a pasted
chat transcript cannot be authenticated (OI-39): F10 cannot
currently tell a genuine reply from a fabricated one.
Two documents give different meanings to CC-01 to CC-07. This
document namespaces them but does not reconcile them (OI-11).
n8n and any other facilitator are unassessed and ineligible by
default (§3.6).

1.9 The Stub-Refuse Consequence
The gate-adapter pattern from MECHA applies. A SAVANT adapter with
no engine behind it returns REFUSED ; a connector adapter with nothing
wired returns REFUSED . A fully built F10 with nothing wired refuses
every run at C1. That is the intended state of an automation layer
whose engine and connectors are unfinished.
PART 2 — EXECUTIVE SUMMARY
Leadership
2.1 Business Context
A creator finishes F0 through F9.5 holding a certified artifact. Getting it
onto a real platform is still manual, platform by platform, and the
Colonization Manual is explicit that the manual work is where cards get
diminished. F10 exists to let the creator connect once and customize
per platform without giving up the discipline.
Automation carries a specific risk. Every failure mode in the Manual's
anti-pattern chapter is a skipped or rushed SAVANT phase. An
automation layer can commit every one of them at machine speed.

This is a third execution class, not a new GRO mode:
execution_class: "AUTOMATED" | "GUIDED" . Every other rule stays
in force. Consent #1 still names the exact content and the exact target
account, still declares a rollback (itself a curated script, or a
documented manual step, for CHAT_ONLY targets), and still requires
the human to act before anything is called staged.
Verification, C6. At each checkpoint, the human reports what the target
chatbot actually said. That report is evidence, not narration: it is
graded HUMAN_SUPPLIED under the same trust model as F11 PDD
v1.3's supplied-source rules (§3.5B there), never upgraded to SENSED ,
and treated as data, never instructions — a reply that contains
something that looks like a system instruction is logged and ignored,
not obeyed. Where the setup produces a normal reachable endpoint
(most do, even after a chat-driven build), a generic endpoint probe — a
minimal reachability and basic-response check, not a full connector —
may supplement the human's report. This does not change the target's
actuation class to API .
Certification, C7. UCG-COL still governs. A GUIDED run's evidence is
what it is: human-reported checkpoints plus, where available, a generic
probe. This can be enough for a certificate once UCG-COL itself is
defined (still blocked by OI-10); it is disclosed as a different — and
currently untested — evidence shape than an automated adapter's (OI-

3.12 The Five Invariants This Document
Introduces
Invariant #25 — SAVANT-Gated Colonization
No F10 run may reach any translate, stage, promote or register step
for a target unless a SAVANT verdict (FIT or CLUSTER) has been
issued by the SAVANT engine in the same run, bound to the artifact
hash and to the SENSE record that run captured. A CLUSTER verdict
is never promoted to FIT. A missing, stubbed or stale SAVANT
engine causes refusal. Every completed run issues an SPK
registered to the parent card. An embedded, robotic or physical-
actuation target is refused unless an F9 run exists for it.
CLASS A. Cannot be disabled by flag or tier, waived by the Owner,
deferred, or applied selectively. Enforced structurally: TranslatedPlan
cannot be constructed without a SavantVerdictRecord , and the type
has no path from CLUSTER to FIT .
Invariant #26 — Consent-Gated Transmission
No F10 run may write to any external target, including a staging
instance, without a consent record naming the exact content and
the exact target account for that action, a credential drawn from the
vault at least-privilege scope, and a declared rollback or an explicit
irreversible-action acknowledgement. Staging and promotion
require separate consents. Dry-run is the default. A facilitator never
holds a standing credential.
CLASS A. Enforced structurally: transmit() accepts only a
ConsentedPlan , which only the consent gate can construct.
Invariant #27 — The Single Operator (new, v2.0)


===== PAGE 48 =====
D36 has exactly one operator. A colonization is certifiable and
promotable only if it was produced by a complete SAVANT ENVOY
run with a recorded f10_run_id . Assembling the same strands,
gates and adapters by hand, in any order, is not an F10 run and
produces no certifiable colonization, however faithfully each
individual step was executed.
CLASS A. Enforced structurally: only the ledger can construct a
CompleteRun , and the UCG-COL adapter rejects a request without one
before transport. The invariant exists because v1.0's model made gate-
skipping undetectable: each owner could truthfully report that their
gate passed while the sequence was never enforced and no refusal
was ever recorded. Sequence integrity is a property of the run, not of
any step within it.
Corollary. SAVANT ENVOY may be succeeded by another operator, but
D36 may never have two concurrent operators. A successor inherits
the run-state contract (IP-167) intact.
Invariant #32 — Curated Chat-Script Integrity (new, v3.1 —
adopted unchanged by F11 HOST CONNECTOR)
Any curated prompt offered to a human for pasting into a target's
own chat interface must trace its underlying claim to a sensed or
supplied fact with provenance, must be atomic with an explicit
human checkpoint, and must never instruct the target's own
assistant to bypass its safety, confirmation or billing-consent
controls, and must never contain, request or coach entry of a secret,
credential or payment detail as chat text. A prompt failing any of
these refuses the whole script at composition.
CLASS A. Enforced structurally: CuratedPromptScript is constructible
only by the Chat Script Composer, only after every prompt passes the
four checks of §3.5A.3, and the containsSecret field has no true
value in its own type.
Invariant #33 — Guided Execution Accountability (new, v3.1 —
adopted unchanged by F11 HOST CONNECTOR)

Where a target's only actuation surface is a chat assistant, a write
may proceed only in GUIDED execution: the human performs it
under their own login, and F10 never holds or requests a credential
for that surface. Every GUIDED step still requires the same consent,
cost declaration where relevant, and rollback as an automated write.
The human's report of the outcome is HUMAN_SUPPLIED evidence,
graded, never upgraded to SENSED, and treated as data — never as

CLASS A. Enforced structurally: the Vault interface has no method that
