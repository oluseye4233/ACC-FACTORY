1.1 Atomic Solution Summary


===== PAGE 4 =====
F11 HOST CONNECTOR takes a codebase, or a runtime that a
colonization needs, and connects it to a hosting provider. It profiles
the requirement, senses the providers, produces a scored hosting
plan, stages the deployment, verifies it, certifies it, promotes it, and
hands it to monitoring.
HOST DJ is the operating SPC, through its three documented
features: the Hosting Selector Engine (HSE), the Deployment
Journey Generator (DJG) and the Seamless Deployment Facilitator
(SDF). HOST DJ serves a request in one of two advice modes
(§3.5A): it advises the best hosting environment, or the user names
an environment and HOST DJ writes a cheat sheet for hosting on it,
or advises against it in a technical report and falls back to the first
mode. F10 hands work to F11 when a colonized artifact needs
somewhere to run. F11 hands the running system to F9.5 for
monitoring.
1.2 HOST DJ Plans. F11 Connects.
HOST DJ, as documented, is an advisory capability: it normalises a
Hosting Requirements Profile, scores hosts, proposes a journey and
emits deployment files. The card describes a journey the human
executes, and the product engine that implements it holds no cloud
credentials and executes no deploy. [ARK] F11 keeps that
boundary at the operator and puts the connection machinery around
it.

1.8 What This Document Does Not Claim
F11 is PRE-BUILD. No provider connector, conductor or adapter
exists. Nothing has touched any hosting provider.
The HOST DJ card is in hand, and it is v1.0 from May 2026. Its
47/50 was scored on its own ten-dimension rubric, which is not
the rubric used for the F9 and F10 cards, so comparability is
unverified. Its HIVE 14D certification is pending by its own
statement. It is an advisory selection card, not an operator
profile for a domain that acts (OI-21).
The card conflicts with the F11 invariants in specific places
(§3.2.4): its CI/CD file deploys to production on every push using
a standing token, its health check reports the database
connected without checking, and one of its integrations claims
to deploy agents directly. Those are ruled on here and are not
adopted as written (OI-31).
The suitability rules are F11's design. Two of the blocking
classes come from the card's own constraints (compliance,
deprecated platforms). The rest are drawn from the Hosting
Requirements Profile fields. There is no score-gap trigger, so a
viable but weaker host is never advised against (OI-34). A user
may name a host outside the registry and supply documents
about it (an Owner decision, §3.5B). Those documents are
lower-trust and cannot be authenticated, so they support advice
only and never execution (OI-35, OI-36).
Execution is deferred by the Owner's own earlier decision. The
Command Centre MVP-PDD classifies "execute the deploy" as
deferred (Class C): it stays advisory and never holds credentials.


===== PAGE 14 =====
F11 is that deferred capability specified. It runs PLAN_ONLY until
the Owner lifts the deferral (OI-22).
UCG-HOST has no threshold, so production promotion is
unreachable (OI-23).
The overlap with OSIRIS's deployment layer is unadjudicated
(OI-24).
The HSE weights are the product's values, unvalidated against
any provider (OI-26).
F10 is itself PRE-BUILD, and its own UCG-COL class is
undefined (OI-10), so the F10 production route is doubly blocked.
1.9 The Default Consequence
Out of the box F11 is ADVISORY . It produces a hosting plan and
refuses at H4. A fully built F11 with no Execution Lift never writes to
any provider. That is the current behaviour of F8-HDJ, and it is the
intended state.
PART 2 — EXECUTIVE SUMMARY
Leadership
2.1 Business Context
Creators finish a build, or a colonization, and then stall at "where
does it run?". HOST DJ already answers the first half in the product:
it scores hosts and lays out the journey. The second half, actually
connecting to a provider, is manual and is where credentials leak,
bills surprise, and unverified things become publicly reachable.
The reason to formalise a domain is not to make hosting faster. It is
to make sure that when hosting does act, it cannot skip the plan, the
consent, the cost ceiling, or F10's verdict.

2.5 SOLVA GAUNTLET Verdict
CONDITIONALLY VIABLE. Published as issued.
Grounds:
1. The operating SPC is in hand and is a selection card, not an
operator profile (OI-21). HOST DJ v1.0 is scored 47/50 on its
own rubric with HIVE certification pending. It does not specify
how it behaves as the accountable operator of a domain that
writes to providers.
2. Execution is deferred by the Owner (OI-22). Until the deferral is
lifted, F11 cannot act.
3. UCG-HOST is undefined (OI-23). Production promotion is
unreachable.
4. The deployment layer overlaps OSIRIS (OI-24), and which
invariant number carries OSIRIS's production standard is
unverified.
5. No provider connector exists or has been assessed (OI-25).
Provider terms, prices and APIs drift.
6. HSE weights are unvalidated (OI-26).
7. Compliance regimes are named but not assessed (OI-27). A
profile can say HIPAA or GDPR; nothing here judges a provider
against them.
8. The Vault and Consent Gate are shared and unbuilt (OI-29).
9. F10 is PRE-BUILD, and the F10 handoff route is blocked by UCG-
COL (OI-10).
10. Seat and score collisions around HOST DJ and VIBE DJ (OI-28).


===== PAGE 22 =====
11. The card conflicts with the F11 invariants in named places (OI-
31): an auto-deploying pipeline with a standing token, a stub
health check, a destructive database step listed as rollback, and
an agent-deployment claim that would bypass F10.
12. Only one of the card's three journey tiers is templated (OI-32).
Tiers B and C are named with step counts and no steps.

In both modes Invariants #28 to #31, the consent gate, the cost

carries provenance, because the card's own step text (commands,
DNS values, plan names) is dated and unsourced (C-F11-28).

The handoff is a protocol between two domains, not a shared

3.13 The Four New Invariants
Invariant #28 — Plan-Gated Hosting
No F11 run may write to any hosting provider unless a
HostingPlan exists in the same run, whose ranking, primary,
fallback and score were recomputed by the HSE Evaluator from
sensed provider data, whose host has a connector adapter and a
deployment profile, and which is bound to the artifact hash, the
profile and the run. A plan is never accepted from the HOST DJ
Adapter as computed. A missing, stubbed or stale evaluator or
provider adapter causes refusal.
CLASS A. Enforced structurally: ConsentedHostingWrite cannot be
constructed without a HostingPlan , and HostingPlan is
constructible only by the Plan Gate.
Invariant #29 — Consent-Gated Hosting Writes
No F11 run may write to any provider, staging included, without a
consent record naming the exact content, the exact account,
project and region, and a cost ceiling, a credential drawn from the
Vault at least-privilege scope, and a declared rollback. Staging
and production take separate consents. Destructive, public-
exposure and DNS actions each need their own consent line.
Environment templates carry keys only and no secret is written to
any artifact, log or ledger. Dry-run is the default.
CLASS A. Enforced structurally: provision() , deploy() and
rollback() accept only a ConsentedHostingWrite , which only the
Consent Gate can construct.


===== PAGE 60 =====
Invariant #30 — F10 Handoff Integrity
F11 accepts a colonization-derived hosting request only through
an F10Handoff built by F10's conductor from a run with a
SAVANT verdict bound to the artifact. A production host requires
a UCG-COL certificate for the colonized deployment. F11 never
makes a colonization's runtime reachable by users before F10's
own promotion consent, and hosting a colonization neither
certifies nor promotes it.
CLASS A. Enforced structurally: F10Handoff is constructible only by
the F10 Conductor, and the Handoff Port has no other intake for a
colonization.
Invariant #31 — The Single Operator (D37)
D37 has exactly one operator. A hosted deployment is certifiable
and promotable only if it was produced by a complete F11 run
with a recorded f11_run_id . Assembling the same plan, gates
and connectors by hand, in any order, is not an F11 run and
produces no certifiable hosting, however faithfully each step was
executed.
CLASS A. Enforced structurally: only the ledger can construct a
CompleteHostRun , and the UCG-HOST adapter rejects a request
without one before transport. Corollary. HOST DJ may be succeeded
by another operator; D37 may never have two concurrent operators.
