# Go-live checkpoint: Agent Creator and IMPRIMA Portal

## Implemented scope

### Agent Creator
- Replaces the new SHORT SPRINTS entry; historical sprint workflows remain.
- Creates a source-bound MA with its actual F4 Micro PDD, or an SPC with a Cheat Sheet.
- Compiles instructions and performs fresh, explicitly internal JCSE/MATHMON assessments.
- Activates the text-only first-party runtime only for eligible scores and SAFE_LIFE GRO.
- Carries the mandatory governance criteria into every run. No tools, browser, file writes or external side effects are granted by this runtime.
- Retains creation/run attempts, request-key idempotency, owner checks and source/companion hashes. Uncertain attempts are not silently redispatched.
- Supports returning a saved agent package to its exact departing production stage as supporting material, not automatic gate approval.
- External handoff continues through eligible existing F10/F11 paths. This does not activate unrestricted F12 or bypass release qualification.

### IMPRIMA Portal
- Central publication surface for owned artifacts, Exemplar sources, completed SPC Player synthesis, authorized historical files/preparations, sprint exports and target-specific F10 packages.
- Professional PDF or editable ZIP with explicit author/publisher, subscriber stamp, publication identity, source hash, UTC date/time and bottom-right ATANDA.IMPRIMA stamp.
- Native files and target packages are retained unchanged beside the stamped publication document.
- Frozen bytes stored privately; no public download URL.
- A six-digit code is emailed to the subscriber profile address, expires in ten minutes, locks after five incorrect attempts, is rate-limited and is single-use.
- Replayed, concurrent, expired, foreign and superseded codes are rejected.
- The exact frozen bytes must first be accepted by the email provider for the designated control recipient. Failed/dry-run/uncertain delivery does not authorize a download.
- Provider acceptance is not proof of final email delivery; a download issuance is not proof that the browser finished saving.
- Legacy project attachment routes are blocked centrally. Routine account/privacy/activity/finance exports remain separate.
- A prepared publication can return to the exact departing stage. Publication does not pass that stage.

## Activation dependencies — not yet a live-availability claim

1. Configure either platform-managed email with a verified `EMAIL_FROM`, or a subscriber/organization-owned Resend or Postmark connection through Account/Organizations → Notifications → Email delivery. Subscriber-owned delivery must pass its inbox-code verification; it does not require the platform Resend connection. See [subscriber email delivery](subscriber-email-delivery.md).
2. Confirm the subscriber profile email and approved control-recipient setting.
3. Verify real code delivery, control-copy acceptance and download once email is configured.
4. Complete the signed-in browser check through the normal staff-access and Clerk gates.
5. Publish only after the existing migration/security deployment checks pass in the deployment environment.

Development implementation and tests do not establish production activation.
No production secrets, roles, security policies or release protections were changed.

## Deliberately separate safeguards

- Internal scoring is not independent XVL/VTE verification or FORGE certification.
- Publication declarations and stamps are not copyright registration, ownership adjudication or a transfer of intellectual-property rights.
- Formatting follows a deterministic KLARITY/SKRIBE-oriented layout; this is not a claim of an independent SPC certification.
- Restricted historical operations still require their existing database role, RLS and immutable-version protections. The Portal does not substitute an owner connection when those protections are unavailable.
- Automatic external execution, target deployment qualification, and general F12 release remain governed by their existing conditions.
