# Integrated F8 conversion — CODE ONE +

## Product flow

F4 creates a platform-neutral Micro PDD: no Target VIBE or early IDE lock.
F6 creates the ATLAS PDD; F7 creates the certified MVP PDD. Each creation
surface offers the actual F10 catalog as a future colonization preference.
This preference is retained as `FAMILY::target`, not interpreted as consent
or a SAVANT FIT verdict.

F8 now contains the former VIBE recommendation responsibility. The separate
F6-VDJ navigation entry and F6 recommendation panel are removed. Legacy
session links with `featureId=8` open F8; the legacy advisory API remains
available for compatibility. No historical artifacts are rewritten.

For software, F8 reuses a saved exact-MVP HOST DJ plan or creates one first.
CODE ONE + then recommends an IDE, coding approach and implementation
platform while producing the corresponding scaffold. An operator can opt
out of automatic platform selection, but cannot override certified scope,
hosting compatibility or governance. The generated manifest must use the
actual HOST DJ primary identifier; metadata is never silently relabeled.

The certified MVP PDD remains the binding source. New F7 artifacts retain
the original ATLAS PDD reference; an owned same-session Micro PDD can be
included as additional context. Legacy MVP PDDs without a reference remain
usable, but no original PDD is invented or selected from an unrelated run.

## Evidence and boundaries

- CODE ONE + v0.2 is an unsigned, uncertified draft specification supplied
  by the user. Its instruction-level adoption is not deployment of its
  complete fixed multi-stage runtime.
- VIBE DJ selection instructions run within the conversion call. HOST DJ
  uses the existing source-bound, server-ranked plan; recommendations
  remain advisory and carry their existing provider-evidence limitations.
- Every new engine invocation uses existing tier/cost controls and engine
  run accounting. Reusing an existing hosting plan avoids another planning
  call. This does not establish exactly-once provider charging after an
  ambiguous network failure.
- The result remains an unverified scaffold, with the existing 12-file
  limit. It is not a claim of complete implementation of every PDD feature.
- Independent ATHENA research, CODON composition, S5b verifier execution,
  the full append-only stage ledger and mandatory pre-packaging BUGMXT
  execution are **not implemented by this conversion change**.
- PFP drift checking, real CI/IDE evidence, independent verification,
  review and release remain separate. A recommendation is never a passing
  drift result. A scaffold inherits no certification.
- Firmware remains human/F9-gated, with no automatic hosting-plan call or
  functional-safety claim. The existing generated language/platform bounds
  are unchanged; this is not native firmware compiler support.
- A colonization preference does not install an adapter, bind provider
  consent, qualify an artifact, activate F10/F11/F12 or bypass closed
  production database guards.
- Mandatory GRO, ZPOS and Honesty Gate safeguards remain required.

## Verification

Offline contract tests cover exact source/context binding, missing or foreign
hosting plans, foreign Micro PDDs, outstanding critical drift, mismatched
platforms, duplicate files, missing entrypoints and hosting-manifest mismatch.
They use explicit synthetic fixtures, not paid provider or certification
evidence. Existing F4/F8 provider replay fixtures require refreshed recordings
for the new prompts and hosting-plan contract before they can attest the new
flow's real provider behavior. No paid calls were made to manufacture those
recordings during this implementation.
