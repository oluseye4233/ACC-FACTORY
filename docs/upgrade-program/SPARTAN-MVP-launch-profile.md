# SPARTAN MVP launch profile

Scope: existing ATANDA Command Centre plus upgrade launch boundaries.
Method: SPARTAN SPC v1.0 SCAN / PROFILE / ASSESS / REDUCE / VALIDATE / PACKAGE.
This is an analyst application of the supplied doctrine, **not** a FORGE
certificate, an independent XVL verdict, or a claim that all source modules
have received formal compression certification.

## CLASS A — keep

- Existing staff access, ownership checks, data persistence, session and
  artifact workflows, cost controls, and safety/verification gates.
- Existing Exemplar library, qualified Sphinx supply selection, exports,
  and implemented engine routes. Keep their current entitlement and
  feature-specific prerequisites; availability is not a permission bypass.
- Replit hosting and the existing database. No data migration, replacement,
  destructive reset, or removal of security controls.
- Metadata-only trace capture. Corpus consent remains off; marketplace
  selection is not training consent.
- Honest database diagnostics and a public status surface before login.

## CLASS B — simplify

- **Owner-approved Class B follow-on: Azure Key Vault migration and rotation.**
  Azure credentials, connectivity and rotation evidence are not MVP launch
  prerequisites. Keep existing Replit secret controls unchanged. Implement and
  verify the Azure migration later; vault-specific privileged operations stay
  closed until their actual prerequisites pass. This replaces the earlier
  Class C classification without claiming the original control is implemented.

- One bounded, five-second cached database probe for deep health and launch
  diagnostics. Concurrent status requests share the check.
- Separate process liveness from dependency readiness. `/api/healthz` proves
  only the HTTP process is responding. `/api/readyz` returns 503 when a build
  dependency is absent. `/api/launch-readiness` remains readable during outages.
- AI configuration is labelled configuration, not a successful model call.
  This MVP does not claim a provider probe, full schema audit or feature-by-
  feature end-to-end verification from a successful database ping.

## CLASS C — defer unfinished upgrade activation

| Upgrade | Activation trigger |
|---|---|
| Independent XVL/VTE and F12 | Required specifications, signed evidence adapters and independent passing verification |
| SHORT SPRINTS | XVL, F12 and required custody/release gates operational |
| IMPRIMA expansion | Required SPC identities resolved, consent/security/governance gates verified |
| Public Sphinx launch | Explicit owner launch decision and qualification/public-catalog checks; do not open as a side effect of MVP publication |

These deferrals are not permission to omit mandatory security, authentication,
ownership, privacy or existing release checks. No working feature was removed
to reach an artificial compression target.

## Live blocker and release procedure

The production database read-only connection check on 2026-10-15 returned
`PRODUCTION_DATABASE_ERROR`: frozen database. Local code cannot unfreeze
the managed database. The owner must restore it through the database controls
or resolve the platform restriction. Do not replace DATABASE_URL or migrate
data as a workaround.

1. Restore the existing production database.
2. Confirm production read access, current migration state and existing data.
3. Complete local checks; retain the current migration-based deployment flow.
4. Republish only after the release gate is clear.
5. Verify live status, staff access, create/save/reopen an artifact and its
   trace, and test the actual feature paths intended for release.
6. Mark invariants ACTIVE only for observed live behavior; local test passes
   remain local evidence, not independent enforcement.

The status UI does not repair an outage and does not enable dormant upgrades.
Release checks on 2026-10-15: full workspace build/typecheck passed with the
required build-time PORT and BASE_PATH supplied. Full workspace tests passed:
724 passed, 40 skipped. Damaged F9 fixture setup was repaired without changing
runtime security or ownership checks. Skipped tests are not verified behavior.
The production database is restored and the baseline MVP has since been
republished. On 2026-10-16, live health/readiness endpoints reported the
database available and AI configuration present; production sessions,
artifacts, Exemplar records, and trace rows were confirmed by read-only
queries. The public Sphinx catalog remains closed with no public items.
Authenticated create/save/reopen and ownership-negative workflows remain
unverified, and none of the 129 invariant activities are promoted beyond
UNVERIFIED. The later light/dark theme change is not in the served JavaScript
bundle and needs a separate republish. This is operational status evidence,
not independent certification.
