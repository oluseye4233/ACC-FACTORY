## ARES security-assessment adapter

**Inputs:** versioned repository/dependency manifests; available security
requirements; scoped environment; actual scanner results; ownership and
negative-test evidence; observed controls. Never request or embed secret values.

**Operations:** map each finding to a control and its evidence; distinguish
scanner finding, verified reproduction, source-stated risk, unknown and
documented exception. Prioritize critical/high findings. Recommendations are
not repairs, and a clean static scan is not proof of runtime isolation.

**Output:** scope/time, finding ID/severity/source, affected package or location,
applicability, evidence, remedy, owner role and unresolved verification. No
numeric composite without a supplied scoring rubric. No active exploitation
of production. See `SEC-REP-ONE-reassessment.md` for actual observations.

## KLARITY publishing-rendering adapter

**Inputs:** owner-authorized manuscript/intake; title and audience; supplied
style; versioned claims, source references and hashes; factual premise review;
requested output format and locale; permitted disclosure scope.

**Operations:** produce clear editorial explanations and a structured
publishing plan using only attributed claims. Preserve quotations and source
provenance; mark generated interpretation, unknowns and research questions.
Never invent citations, research outcomes, reviewer approval, publishing
rights or permissions. Content screening is not legal review.

**Output:** draft sections, claim/source map, unresolved questions, accessibility
and format checklist, and revision references. Rendering success cannot set an
IMPRIMA verification, legal, rights or release gate to passed. No public
publication occurs without the existing explicit publishing/release action.

## SOCRATES premise-review adapter

**Inputs:** premise/claim; supplied supporting and contradicting material;
discipline; source identities, dates, availability and version hashes.

**Operations:** clarify the proposition; identify assumptions and falsifiable
tests; distinguish logical consistency from empirical support; consider
contradictions/retractions when those sources are actually checked. Unknown
source status remains unknown, not evidence that no contradiction exists.

**Output:** `SUPPORTED`, `CONTESTED`, `UNSUPPORTED` or `UNASSESSABLE`; reasoning
with exact source pointers; counterarguments; unanswered questions; suggested
tests and expert escalation. This is advisory analysis, not I3 review or
scientific validation. Unsupported scientific premises cannot become release
clearance through a logically consistent argument.

## Minimal PLAN governance bridge

Every proposal identifies its source versions, owner scope, relevant invariants,
dependencies, unknowns, acceptance tests and expected operational impact.
Approval records require an authenticated authorized actor, reason, time,
scope, content hash and, for a waiver, expiry. Chat permission to implement is
not a signed approval of future generated artifacts.

Changes preserve artifact lineage; privacy/training permissions are distinct;
failed checks stay failed or inconclusive until new real evidence resolves
them. No upgrade control may claim that a prerequisite was satisfied merely
because this bridge contract has been written.
