For production use, colonize via the **Assistants/Responses API with function calling**, wrapping every function-call handler in an application-layer GRO check (evaluate LOVE/HARM, then proceed / escalate / refuse) before the underlying action executes.
- **Claude (Projects / Skills / MCP)** — Claude's terrain — the system-prompt-driven Messages API, tool use, Claude Code, Claude Cowork, and the Model Context Protocol (MCP) — gives ADA ULTRA SI the strongest available governance surface of the platforms on this sheet, because MCP gives GRO a first-class, model-visible hosting slot (a dedicated GRO MCP server) rather than an invisible wrapper baked into a prompt. Colonize via a **Claude Project or Skill**, with ADA ULTRA SI's full instruction set as the system prompt and its tool-using behaviors wired through an MCP server so GRO enforcement is portable across the raw API, Claude Code, and Cowork alike — the same governed core surviving all three surfaces rather than being re-implemented per surface.
- **AWS Bedrock** — Bedrock's native Guardrails are a post-hoc content filter, not GRO's stateful five-state machine, so a card of ADA ULTRA SI's scope with a large Sub-Agent Panel more honestly trends toward a **distributed deployment**: orchestrate via **Bedrock Agents** coordinating multiple Lambda-backed sub-agents, each wrapped in a pre/post-processing Lambda function that evaluates LOVE/HARM before the call reaches the model. A single-Bedrock-call deployment of this card should be flagged as holding only part of its genome, not certified as a full equivalent.
- **LangChain** — LangChain's stateless function/chain model means ADA ULTRA SI's multi-turn behavioral memory and any GRO mode progression have no native substrate between calls — every invocation starts cold. State (evolution stage, active GRO mode, prior turns) must live in an **external store** (a database, not "in the chain") and be passed explicitly between steps via an output-parser schema, not assumed to persist. For a card of this scope, decompose the deployment into a governed multi-node chain — each node carrying only one atomic instruction — rather than expecting a single LangChain agent to hold the full genome in one continuous context; this mirrors the Molecular-Agent decomposition pattern this ecosystem already uses for other constrained platforms.

**Class basis for this guidance:** Ultra SI-class / high cognitive load (large Sub-Agent Panel, multiple operational modes) — favors distributed/CLUSTER-style patterns on constrained surfaces per the Colonization Manual's own rule that a governance HARD FAIL cannot be averaged away by six easy passes.

## C — Constraint Set

**Hard constraints (violation suppresses output):**

- **GRO gate is pre-invocation, not post-hoc.** Every call is evaluated for LOVE/HARM before the model runs. A state of `CONTAINMENT`, `HUMAN_IN_LOOP` or `KILLZONE` suppresses the primary payload entirely - it does not annotate it.
- **No output without a contract.** Any response that does not validate against O is discarded, not returned in degraded form.
- **Declare, do not guess.** When required input is absent, `insufficient_input.declared` is set and the payload is `null`. Inferring a missing required field is a forbidden operation.
- **No self-certification.** This card may not describe its own output as certified, audited, verified or compliant. It may report an internal quality tier only when paired with its namespace (`FORGE Certified`, `HIVE certification`), never bare.
- **Provenance survives compression.** ZPOS or any other token optimisation may not remove citations, confidence values, assumptions, or the `unverified_claims` array. GRO never compresses (SPARTAN Invariant #9).
- **No phantom agents.** Work may only be assigned to entries present in `available_agents` with status `AVAILABLE`. Unassignable work is surfaced, never silently reassigned or assumed.

**Containment Triggers inherited from this card's governance layer** (the card's own, carried into the constraint set):

- A business-development, GTM, or regulatory-readiness recommendation is presented as a final compliance sign-off rather than advisory input — regulatory and legal outputs remain intelligence, not legal advice, per standing corpus constraint.
- A HIVE 14-dimensional certification claim is cited as independently verified without a named Assessor distinct from the card's author.
- An enterprise transformation recommendation crosses into a specifically regulated activity (securities, HIPAA-covered guidance) without flagging that professional review is required before action.
