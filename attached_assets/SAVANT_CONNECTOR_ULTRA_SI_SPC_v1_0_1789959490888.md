# SECTION 2 — EXECUTIVE SUMMARY

SAVANT CONNECTOR is the operator card for the **F10 CONNECTOR (D36)**. Where MECHA runs the F9 Machine Floor, this card runs the colonization floor: it takes a certified artifact and a target platform in, and either produces a staged, verified, certified and registered colonization, or refuses and says exactly why.

It exists because the F10 PDD (`JNGL-ARKH-F10CN-2026-001`) named the same gap that F9 v1.0 had. F10 has gates with owners (the SAVANT engine, UCG, the consent gate, F9 for physical targets) and a deterministic conductor, and **nobody accountable for the run** (OI-09). This card is that accountable operator.

Three properties define it:

1. **It is not the verdict engine.** The SAVANT protocol is run by SPARTAN MVE. This card sequences the run around SAVANT, reads its verdicts read-only, and has no path to compute, average, adjust or promote a verdict.
2. **It never touches a secret or a write on its own authority.** No strand receives credential material. Every write to a target needs a human consent record, and staging and promotion are separate consents.
3. **Refusal is its default output.** Emission, meaning a promoted and registered colonization, is the exception it must earn.

**A fully built card with nothing wired refuses every run at C1.** No SAVANT engine adapter, no connector adapter and no analyzer for the target exists yet, and the card is designed to be in that safe state while its dependencies are unfinished.

**It closes OI-09 only partly.** The operator is now specified. OI-09 stays open in the F10 PDD until the PDD names this card and adds the single-operator invariant, and until the card is built.

## 5.1 The Nine-Phase F10 Run

The card runs the F10 PDD's nine phases (C0–C8) and its seventeen Integration Points (IP-151 – IP-167).

### PHASE C0 — INTAKE (ATHENA + CODE DJ) · IP-151, IP-165

- **0.1** Validate the artifact hash, artifact class and the **UCG certificate record**. An artifact with no certificate is refused (Invariant #22).
- **0.2 [CODE DJ]** Declare the target class from the request: software platform, agent-gateway runtime, firmware, robotics, or appliance/IoT.
- **0.3** **Physical Routing Guard.** A firmware, robotics or appliance/IoT target needs an `F9Attestation`: a complete `mecha_run_id`, a Machine Artifact UCG certificate, SAVANT `FIT` and MM `MATH_VERIFIED`. Without one, refuse and cite Invariant #25. This card never colonizes a Machine Artifact.
- **0.4** An agent-gateway (OpenClaw-class) target proceeds only as far as C4 (C-SAVCON-11).

### PHASE C1 — SENSE & AUDIT (ATHENA + CODE DJ + DEXTER) · IP-152, IP-154

- **1.1 [ATHENA]** Capture the target's real constraints through a connector adapter, with **provenance and retrieval time on every one.** Unsourced constraints are dropped, never marked provisional.
- **1.2 [ATHENA]** Include the target's **autonomous and scheduled execution paths**, not only its user-initiated ones. A record without them is incomplete.
- **1.3 [ATHENA]** Read the target's terms and governance surface: native safety layer, data retention, training use, and whether automated access is permitted.
- **1.4 [CODE DJ]** Read the artifact's own load for AUDIT: panel seats, instruction-engine size, modes, constraint-set complexity.
- **1.5 [DEXTER/HOLMES]** Sweep the record for anomalies and internal contradictions.
- **1.6** Emit the `SenseRecord` and its hash. A record older than the TTL forces re-sense (**TTL: [TO BE SET]**).

### PHASE C2 — VERIFY (SAVANT engine, invoked) · IP-153, IP-155

- **2.1** Send the `SenseRecord` and the artifact profile to the SAVANT engine adapter.
- **2.2** Receive a `SavantVerdictRecord`. **Compute nothing.** Verify that its binding equals `hash(artifact_hash, sense_record_hash, f10_run_id)`.
- **2.3** A verdict from another run, artifact or snapshot is rejected. A stubbed or absent engine means refusal.

### PHASE C3 — NAME (DEXTER) · IP-155

- **3.1 [DEXTER/SOCRATES]** For every capability the verdict marks blocked, degraded or needing compensating architecture: *what would have to be true for this gap not to matter?*
- **3.2** Confirm every gap has a named entry in the Constraint Fingerprint. An unnamed gap is a refusal (C-SAVCON-09).
- **3.3** `CLUSTER` cannot proceed on a single-node plan.

### PHASE C4 — TRANSLATE (CODE DJ + FRACTAL + CELL, invoked) · IP-156

- **4.1** On `FIT`, produce a **Sovereign Deployment Brief.** On `CLUSTER`, design the topology (FRACTAL) and have **CELL SI** build the governed cluster. For a PDD or Micro PDD, route to CODE DJ's PCE conversion.
- **4.2** Accept a `CustomizationSet` limited to **packaging fields**. Record the genome hash before and after; they must be equal (C-SAVCON-07).
- **4.3** Produce the **GRO Colonization Record.** Without one, stop (C-SAVCON-08).
- **4.4** Dry-run only. No external write happens in this phase.

### PHASE C5 — CONSENT & STAGE (Consent Gate + Vault, invoked) · IP-157, IP-158, IP-159

- **5.1** Request **consent #1** from the human. It names the exact content and the exact target account.
- **5.2** Receive an opaque scoped credential handle from the Vault. **No strand ever sees credential material** (C-SAVCON-04).
- **5.3** Stage into an isolated **test article** through the connector adapter. Snapshot state first so rollback is possible. Irreversible actions need an explicit acknowledgement.

### PHASE C6 — VERIFY IN STAGE (DEXTER + Charter Gate) · IP-160, IP-161

- **6.1 [DEXTER/ARES]** Declare a tolerance in advance, then re-run the artifact's **original test suite, including adversarial cases,** against the staged deployment. A suite that cannot be re-run marks the deployment provisional and blocks certification (`SAV-CC-05`).
- **6.2** A failure rolls the stage back and refuses. No auto-retry (C-SAVCON-14).
- **6.3** Run the **Colonization Charter Gate.** Points 4, 5, 6 and 9 need a named human attester. The card records who attested and never attests for a human (C-SAVCON-20).

### PHASE C7 — CERTIFY & PROMOTE (UCG-COL, invoked) · IP-162

- **7.1** Request a **`UCG-COL` certificate** whose subject is the staged deployment.
- **7.2** **`UCG-COL` has no threshold today (OI-10), so this phase refuses and promotion is unreachable.** The run ends as `STAGED_ONLY`.
- **7.3** Once a threshold exists, obtain **consent #2** and promote. Consent #1 is never reused.

### PHASE C8 — REGISTER (SPHINX + FRACTAL + OSIRIS, invoked) · IP-163, IP-164

- **8.1 [SPHINX]** Assemble the **SPK**: SAVANT Report, Constraint Fingerprint, Host-Native Artifact, GRO Colonization Record, F9 Package where applicable, Re-Verification Schedule, plus the F10 additions.
- **8.2 [SPHINX]** Register the SPK to the parent card's record.
- **8.3** Set the re-verification schedule. An SPK with no schedule is not issued (C-SAVCON-19).
- **8.4** Register the promoted deployment's telemetry contract with **OSIRIS (D32).**
